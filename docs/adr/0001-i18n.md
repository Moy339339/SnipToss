# ADR-0001 Multilingual architecture

- Status: accepted (2026-10-17)
- Related: `docs/annotation-format.md` "Folder settings" (the language of REVIEW.md); `CONTRIBUTING.md` "UI text", "Translations"

## Context
1.0 supports 11 languages. The default follows the Windows display language and can be changed in Settings. There was no i18n infrastructure:
about 1,070 lines of the web UI and about 375 lines of the C# shell contained Chinese; sentences were assembled from fragments, plurals and
measure words were hand-written, and some logic depended on Chinese text (`label === "适合"` in `ZoomView.tsx`).
User-visible text lives in three places: the web UI, the C# shell (tray, capture overlay, clipboard text, the caption drawn into screenshots),
and the text written for AI (REVIEW.md, text copied for AI, command-line output).

## Decision
1. **One set of messages, shared by all three places**: `i18n/locales/<lang>.json`, ICU MessageFormat syntax, split by prefix:
   `app.*` (web UI), `shell.*` (tray, windows), `capture.*` (capture overlay), `ai.*` (REVIEW.md, text copied for AI, the caption of a screen capture note), `cli.*` (command line).
2. **The web UI uses FormatJS** (`react-intl`, with `@formatjs/cli` for extraction and validation; TS types are generated for the keys, so a missing key fails at compile time).
3. **C# uses MessageFormat.NET** (it ships CLDR plural rules) and reads the same JSON. C# messages use only placeholders and `plural` / `select`;
   date and number ICU sub-formats are not used (those go through `CultureInfo`).
   The implementation uses 8.0 (released 2026-02: plural and ordinal rules follow CLDR 48, the hard-coded English rules are gone, supports net10.0), not the 7.x that was current when this item was drafted.
   **Cross-side consistency test**: the same "message + arguments" must format to exactly the same string in TS and C# (`tests/golden/messages.json`: the messages the shell uses,
   in every language, with the various plural and select values; computed with intl-messageformat by `packages/web/test/messages-golden.test.ts` and compared by `tests/AppTests/LocaleTests.cs`).
   Known difference: `#` and number placeholders get no thousands separator in C# (intl-messageformat writes 1,234). Shell messages use numbers only for ordinals, counts and pixels,
   and every number in the golden file is below 1000.
4. **Languages** (11, in two tiers):
   - Tier 1 (a missing message blocks the release; every message is reviewed by a person): `zh-CN` (source language), `en`
   - Tier 2 (a missing message falls back to `en`; marked "native speakers welcome to review"): `zh-TW`, `ja`, `ko`, `fr`, `de`, `es`, `it`, `pt-BR`, `ru`
5. **Detection**: the shell reads `CultureInfo.CurrentUICulture` and maps it: `zh-Hans*` / `zh-CN` / `zh-SG` → `zh-CN`; `zh-Hant*` / `zh-TW` / `zh-HK` / `zh-MO` → `zh-TW`;
   `pt-*` → `pt-BR`; anything else matches on the language part, falling back to `en`. The `language` setting is `"system"` (default) or a language code.
   Before the page loads, the shell writes the current language with `AddScriptToExecuteOnDocumentCreated`, so the web UI has that language's messages before the first paint and never flashes the wrong language.
6. **Switching takes effect immediately**: the web UI re-renders; the shell reloads its own messages (the tray menu and the capture overlay use the new language the next time they open). No restart.
7. **Text written for AI**:
   - Text copied for AI, and the clipboard text and the caption under the image of a screen capture note: follow the UI language.
   - REVIEW.md: uses **the language the notes folder was created in**, stored in the data folder (the format document gets this item first). The command line generates it the same way.
     This way people using different languages in one project do not keep rewriting REVIEW.md back and forth.
   - Implementation (since Beta 56): stored as `language` in `.sniptoss/project.json` (`docs/annotation-format.md` "Folder settings"). If the file does not exist yet: a folder that already has a REVIEW.md
     (written by earlier versions, always in Chinese) records `zh-CN`; otherwise the UI language at that moment is recorded (for the command line: the system display language if its `ai.*` messages are fully translated, otherwise English).
     `core` carries no messages; the caller passes a lookup function (`Translate`).
8. **Things that carry no language**: file names (screen capture files are named `capture-<time>.png`; cleaning up old files still recognizes the old Chinese names),
   enum values in the data format (`change`, `resolved`, ... are English already), registry key names.
9. **Formatting**: dates, times, numbers and file sizes use `Intl.*` / `CultureInfo`; sorting uses `Intl.Collator(current language)`; the video timecode `mm:ss.mmm` is not localized
   (it is how people and AI refer to a point in time).
10. **Shortcuts and keyboard layouts**: letter keys match on `e.key`, falling back to `e.code` on non-Latin layouts (Russian, Korean, ...); symbol keys (`[ ] , . \ ? =`) always match on `e.code`. All of this lives in `keys.ts`.
    What it actually does (`keys.ts` is authoritative): digit keys match by key position (on a French layout the unshifted key types `&` and still counts as 1; Shift+digit is recorded as Shift+1);
    symbol keys match by the symbol typed, including symbols typed with AltGr (German AltGr+8 = `[`;
    while AltGr is held, digit keys do not match by position — WebView2 reports `ctrlKey` and `altKey` as false for AltGr, and only `getModifierState("AltGraph")` is true);
    if the name computed from the key position has no shortcut bound and the typed character is a symbol, the lookup is retried by symbol (the `?` of the Russian layout sits on Shift+7).
    Menu mnemonics are part of the messages (`"&File"`, `"文件(&F)"`); each language picks its own letter.
11. **Fonts**: `<html lang>` follows the current language; `:lang(ja)` Yu Gothic UI, `:lang(ko)` Malgun Gothic, `:lang(zh-TW)` Microsoft JhengHei UI, `:lang(zh-CN)` Microsoft YaHei UI,
    Latin text Segoe UI Variable. The font used to draw text in the capture overlay is chosen by language the same way. In non-Chinese UIs the brand font is re-subset using the English name.
12. **Guarding against regressions**: a lint rule forbids bare strings in JSX and user-visible attributes (a warning at first; an error once the full internationalization is done);
    a pseudo-locale `en-XA` (40% longer, accented letters; development builds only) runs through all UI screenshots plus automatic overflow detection.
13. **Logs are not translated**: the shell's `Log.*` and the UI's `logError` write diagnostics for maintainers, always in one language (currently English), independent of the user's UI language.
    If every bug report arrived with a log in a different language, it could not be matched against the code. `scripts/check-i18n.mjs` does not count these lines.
    User-facing text that shows up inside a log (for example a notice recorded verbatim) is not a missed translation.
14. **The one raise of the ratchet**: `core` 68 → 76. (The ratchet is the cap on hard-coded Chinese lines that `scripts/check-i18n.mjs` enforces; it may only go down.) The text for AI gained category descriptions, "file not found" and "written before the item was modified".
    The `core` text for AI (item 7) has no message mechanism until the full internationalization, so these sentences had no compliant place to live, and pushing them into the UI and passing them in would only have moved the problem.
    **The caps for the UI (web) and the shell stay as before: they may only go down.** If `core` needs more text for AI later, build the message mechanism of item 7 first.

## Rejected alternatives
- **i18next**: works well in the web UI, but there is no decent .NET implementation, so the C# shell would need a separate system and the two message sets would drift apart.
- **.resx for C#, JSON for the web UI**: translators would have to maintain two formats, and a community translation platform would need two projects.
- **Bundling every language into the main JS**: eleven languages in the first-paint bundle slow startup; only the current language is loaded, on demand.
- **Text for AI always in English**: the note text the user wrote is in their own language, and wrapping it in English instructions just mixes languages; AI can read either.

## Consequences
- `CATEGORY_LABEL`, `KIND_LABEL` and similar in `core` become message lookups; the duplicate `KIND_LABEL` in `StageHeader.tsx` is removed.
- The `appInfo` that the shell passes to the web UI gains `language` and `systemLanguage`.
- Translation workflow: agree on a glossary first (`i18n/glossary.md`); after the first translation, spot-check with back-translation; after 1.0, connect Weblate to collect community review.
